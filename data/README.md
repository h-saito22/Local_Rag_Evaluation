## qa/qa_v1.csv（48問 ＝ 4種類 × 12問）

| 種類（type） | 意味 | 何を測るか |
|---|---|---|
| same | 資料と同じ言葉で聞く | 基本の検索・回答 |
| paraphrase | 社員がふだん使う言葉で言い換えて聞く | 文脈理解の強さ（10/8 に qwen3:8b が弱かった点） |
| table | 表の中の値を聞く | 表を含むチャンクの検索と読み取り |
| none | 資料に書いていないことを聞く | 創作（ハルシネーション）しないか |

### 列の意味
| 列 | 内容 | 使う指標 |
|---|---|---|
| id | S=same, P=paraphrase, T=table, N=none ＋ 番号 | |
| question | 質問（評価スクリプトがこのまま使う。手入力しない） | すべて |
| expected_answer | 模範解答（none は「資料に記載がありません」） | LLM 採点 |
| keywords | 回答に含まれているべき言葉（複数は `|` 区切り）。none は空 | キーワード一致 |
| source_file / section | 答えがあるファイルと見出し。none は空 | hit@k・MRR |
| evidence | 答えの根拠になる文の一部（文書にちょうど1回だけ出てくる文字列）。none は空 | hit@k・MRR（取り出したチャンクにこの文字列が含まれていれば「当たり」） |
| checked | **人が確認したら記入する欄**（例：OK／修正済み） | |
| note | 補足（ひっかけの意図など） | |

## 確認の手順（人がやること）
1. 1問ずつ、docs/ の該当ファイルを開いて、expected_answer と evidence が正しいか確かめる
2. 質問の言い方が不自然なら直す（特に paraphrase は「社員が本当にそう聞くか」）
3. none は、本当にどの文書にも書いていないか確かめる
4. checked 欄に記入する
5. 確認が終わったら、このファイルを「ものさし」として固定する（あとで変えたら、ファイル名を qa_v2 にする）

## 正解の定義（10/12 決定）
- 資料にある質問（same / paraphrase / table）
  - 正しい答え（keywords）が含まれていても、同じ回答の中で「資料に記載がありません」とも言っている（自己矛盾している）回答は **不正解**
  - 例：10/8 の qwen3:8b「資料に記載がありません。…正解：40日」→ 不正解
- 資料にない質問（none）
  - 「資料に記載がありません」と答え、それ以外のことを付け加えていない回答だけを **正解** とする
  - 「関係しそうな文章」を示した回答は **不正解**
- 決めた理由：
  - キーワード一致だけでは、10/8 の qwen3:8b のような自己矛盾した回答（「資料に記載がありません」と言いつつ正しい数字も書く）を「正解」にしてしまう。ユーザーが読んだら迷う回答は不正解とする
  - 正解の定義を変えると、どのプロンプトが良いかの結論も変わる。10/8 の「縛りをゆるめたプロンプト」は、資料にない質問で関係しそうな文章を示すので、この定義では none が全問不正解になりそう
  - 採用している「縛りが強いプロンプト」は、資料にないときの返答が「資料に記載がありません」と一字一句決まっているので、評価スクリプトで判定しやすい

## 判定ルール（評価スクリプトで使う）
| 質問の種類 | 回答に「資料に記載がありません」が | 判定 |
|---|---|---|
| 資料にある（same・paraphrase・table） | 入っている | 不正解（キーワードが入っていても） |
| 資料にある | 入っていない | キーワード一致＋LLM 採点で判定 |
| 資料にない（none） | 入っていて、ほかに何も付け加えていない | 正解 |
| 資料にない | 入っていない、または関係しそうな文章も示している | 不正解 |

- 決まった言葉で見つけられない言い回し（「明記はないが」など）は、LLM 採点で拾う
- 検索（evidence による hit@k）と、回答の正しさ（上の表）は別々に測る。evidence が取り出せていても、回答が自己矛盾することはある（10/8 の実験）
